# 第1回 解答

## 演習

### 素のLLMへの質問

- 実行コマンド：`uv run python -m app.ask "LoRAとは何ですか？"`
- デフォルトモデル：`gemini-3.5-flash-lite`
- 温度指定できるようにするため、`AIE_TEMPERATURE` 環境変数と `GenerateContentConfig.temperature` を実装した。
- 入力トークン数と出力トークン数を `response.usage_metadata` から取得し、`app/ask.py` に表示できるようにした。

### 講座に固有の質問

- 質問：`AIE2026の講座の宿題にある「3レベル」とは何ですか？`
- 素のLLMへの回答は、講座固有の正確な構成を知らず、一般的な説明になりやすいものだった。
- 用語集の正しい意味は、「基礎（講義内容の確認）・実装（自分でコードを書く）・発展（調査や試行）」の3段階で構成されており、どれか1つに取り組めば宿題は完了するという内容だった。
- 素のLLMだけでは講座固有の情報を正確に参照できないため、用語集やツールを使った参照が必要だと気づいた。

### トークン数の確認

- `gemini-3.5-flash-lite`、temperature `0.0` でLoRAについて質問した場合：入力7トークン / 出力577トークン
- `gemini-3.5-flash-lite`、temperature `0.7` でLoRAについて質問した場合：入力7トークン / 出力607トークン
- `gemini-3.5-flash-lite`、temperature `1.5` でLoRAについて質問した場合：入力7トークン / 出力748トークン

## 宿題

### 基礎

- 取り組んだレベル：基礎
- やったこと：
  - 同じモデル `gemini-3.5-flash-lite` で、同じ質問「LoRAとは何ですか？」を3回実行した。
  - temperature をそれぞれ `0.0`、`0.7`、`1.5` に設定した。
  - 回答の内容差と入力・出力トークン数を記録した。
- 結果：
  - temperature `0.0`：入力7トークン、出力577トークン
  - temperature `0.7`：入力7トークン、出力607トークン
  - temperature `1.5`：入力7トークン、出力748トークン
  - すべての回答で、LoRAを大規模モデルの効率的な追加学習・ファインチューニング技術として説明した。temperatureが高くなるほど、回答の表現や説明量に変化が出た。
- 気づき・疑問：
  - 同じモデルでもtemperatureを変えると、回答の表現や長さが変わるため、出力が確率的であることを確認できた。
  - 入力トークン数は同じだった一方、temperatureが高いほど出力トークン数が増えたが、必ずしも内容の正確性や品質が向上したとは限らない。
  - `gemini-2.5-flash` はこのAPIキーでは404になり、新しいモデルへの変更が必要だった。

### 実装

- 取り組んだレベル：実装
- やったこと：
  - `app/ask.py` に `--chat` オプションを追加し、会話履歴を保持して対話できるモードを実装した。
  - Gemini SDK の `types.Content` と `types.Part` を使い、過去のユーザー質問とモデル回答を履歴として保持した。
  - `generate_content` の `contents` 引数へ履歴を渡し、次の質問でも前の会話内容を参照できるようにした。
  - `exit` または `quit` で対話を終了できるようにし、空入力やEOF、Ctrl+Cも扱えるようにした。
  - `AIE_TEMPERATURE` によるtemperature指定と、入力・出力トークン数の表示も利用できるようにした。
- 結果：
  - 実行コマンド：`uv run python -m app.ask --chat`
  - 既存の一問一答モードも維持した。
  - `--chat` モードは正常に起動し、終了コマンドとEOFを確認した。
  - 既存テスト11件はすべて成功し、構文チェックも成功した。
- 気づき・疑問：
  - 会話履歴を送ることで、前の質問を参照するような「それは何ですか？」といった回答が可能になる。
  - 履歴を無制限に保持するとAPI入力トークン数が増え、コンテキストウィンドウの上限や無料枠の制限に影響するため、長い対話では履歴の制限や要約が必要になる。

### 発展

- 取り組んだレベル：発展
- やったこと：
  - API呼び出しの経過時間を `time.perf_counter()` で計測し、`[応答時間]` と秒数で表示する機能を追加した。
  - 「ミカンは何ですか？」「ブドウは何ですか？」「ゾウはなんですか？」の3質問を、`gemini-3.5-flash-lite` と `gemini-3.5-flash` の2モデルで比較する。
- 結果：

| モデル | 質問 | 応答時間 | 入力トークン | 出力トークン | 回答の傾向 |
|---|---|---:|---:|---:|---|
| `gemini-3.5-flash` | ミカンは何ですか？ | 8.226秒 | 6 | 331 | 原産地、品種、特徴、栄養、産地まで多角的に説明 |
| `gemini-3.5-flash` | ブドウは何ですか？ | 8.617秒 | 6 | 463 | 概要、品種、用途、栄養、旬まで詳細に説明 |
| `gemini-3.5-flash` | ゾウはなんですか？ | 7.706秒 | 7 | 318 | 哺乳類としての特徴、食性、知能、種類を説明 |
| `gemini-3.5-flash-lite` | ミカンは何ですか？ | 1.565秒 | 6 | 220 | 温州ミカン、特徴、栄養、旬を簡潔に説明 |
| `gemini-3.5-flash-lite` | ブドウは何ですか？ | 2.386秒 | 6 | 494 | 概要、品種、用途、栄養、旬を詳しく説明 |
| `gemini-3.5-flash-lite` | ゾウはなんですか？ | 2.478秒 | 7 | 511 | 分類、特徴、種類、食性、保護状況まで詳しく説明 |

- 観測できた結果：
  - Flashでは、ミカン、ブドウ、ゾウのすべてに対して、それぞれ6〜7入力トークンに対する詳細な回答が生成された。
  - Flashの出力は318〜463トークン、応答時間は7.706〜8.617秒だった。
  - Flash Liteでは、出力は220〜511トークン、応答時間は1.565〜2.478秒だった。
  - 今回の実行では、Lite版が全3質問でFlash版より応答時間が短かった。
  - Flash Liteのゾウへの回答が最も出力が多く511トークンだったのに対し、Flash版ではブドウへの回答が463トークンで最も多かった。
- 気づき・疑問：
  - 応答時間には、ネットワークやサーバー負荷も含まれるため、モデル性能だけを比較する指標にはならない。
  - 入力トークン数はほぼ同じ短い質問だったため、出力トークン数や応答時間の違いは、モデルだけでなく質問内容と生成量の影響も受ける可能性がある。
  - 一回の実行結果なので、正確な高速性能の比較には、複数回の測定と平均・ばらつきの記録が必要になる。
  - レート制限（429）や無料枠の残量は実行した時点で記録しておく必要がある。
